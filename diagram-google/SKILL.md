# Diagram Google

Googleの最新機能・アップデートを**自分がすぐに使いこなせる**図解HTMLに変換する。
「知る」で終わらず「使える」状態になることがゴール。

**制約（必ず守る）:**
- **1図解 = 1機能** — 複数の機能があっても最も重要な1つだけを扱う
- **読了5分以内** — セクションは最大4つまで。情報は絞る

## 依存

- `references/html-structure.md` — GoogleテーマのHTMLテンプレートとデザインガイド
- `references/google-products.md` — Googleプロダクト一覧と検索クエリのコツ
- `references/exemplar.md` — 成功パターンと品質チェックリスト

## ワークフロー

### Phase 0: 最新情報リサーチ（サブエージェント）

**exploreサブエージェント**を起動して、対象のGoogle機能を徹底調査する。

```
Task({
  subagent_type: "explore",
  description: "Google最新機能の調査",
  prompt: `
    以下のGoogle機能・アップデートについて徹底的に調査してください：
    【対象】{機能名 or URL}

    調査項目：
    1. 何が変わったか（旧→新の変化点）
    2. どこで使えるか（対象製品・プラン・地域）
    3. 具体的な操作手順（ステップバイステップ）
    4. フリーランス・個人が活用できるシーン
    5. 発表日・リリース日
    6. 公式ドキュメントやブログのURL

    結果は箇条書きで整理して返してください。
  `
})
```

### Phase 1: Webで最新情報を直接収集

リサーチ結果を補完するため、WebSearchとWebFetchで情報を収集する。

- **検索クエリの参考** → [references/google-products.md](references/google-products.md)
- URLが渡された場合は `WebFetch` で直接取得する
- 公式ソース（Google公式ブログ・ヘルプセンター）を優先する

収集する情報:
- 変更点の正確な説明（公式の言葉を優先）
- スクリーンショットの代わりになる操作の説明
- 活用できる具体的なシーン
- 出典URL（インライン出典に使う）

### Phase 2: 情報を整理する

**複数の機能が見つかった場合は、最も実用的な1つだけを選ぶ。** 残りは捨てる。

以下の観点で選んだ1機能を構造化する:

| 項目 | 内容 |
|------|------|
| 一言サマリー | 「これで何ができるようになった？」を1文で |
| 変更前 | 今まではどうだったか |
| 変更後 | 今はどうなったか |
| 対象製品 | Google Workspace / Google検索 / Gemini など |
| 使える人 | 全ユーザー / 有料プランのみ など |
| 操作手順 | 実際に使うための具体的なステップ |
| フリーランス活用 | AI学習・副業・フリーランス業務での使いどころ |

### Phase 3: HTML生成

収集した情報をもとに、図解HTMLを生成する。

**詳細** → [references/html-structure.md](references/html-structure.md)

コンテンツ構成（この順番で）:

1. **ヘッダー** — 機能名 + Google製品バッジ + 発表日
2. **一言サマリーカード** — 核心を1文で + ビフォーアフター + 利用条件バッジ
3. **今すぐ試せる手順** — 番号付きステップ
4. **フリーランス活用ポイント + 出典** — ユースケース + 出典リンクを同じカードにまとめる

補足・注意点は「フリーランス活用ポイント」カード内の箇条書きに収め、セクションを増やさない。

### Phase 4: ファイルを保存

1. `output/` ディレクトリがなければ作成する
2. 機能名に関連する短い英単語のスラッグを決める（例: `gemini-workspace`, `search-ai-overview`）
3. ファイルを `output/{スラッグ}.html` として保存する

### Phase 5: デプロイ

Node.jsの有無を確認する:

```bash
node --version
```

バージョン番号が表示された → そのまま「公開の実行」に進む。

`command not found` と表示された → Node.jsのインストールが必要。インストール方法を案内する。

#### 公開の実行（Windows PowerShell）

```powershell
npx --yes surge output/{スラッグ}.html --domain diagram-{スラッグ}.surge.sh
```

#### 初回の場合（Surge未登録）

ターミナルにメールアドレスとパスワードの入力を求められる:

> 初回のみアカウント登録が必要です。
> メールアドレスを入力して Enter → パスワードを決めて入力して Enter。
> 確認メールが届いたらリンクをクリックすれば登録完了です。
> 次回以降はこの手順は不要です。

#### よくあるエラーと対応

- **`npx: command not found`** — Node.jsが入っていない。インストールを案内する
- **`surge: not found`** — `npm install -g surge` を実行してから再度試す
- **認証エラー** — `npx surge login` を実行してメールアドレスとパスワードを入力する

### Phase 6: 完了報告

#### 公開に成功した場合

```
完成・公開完了: 【機能名】の図解

（変更点を1〜2文で要約）

公開URL:
https://diagram-{スラッグ}.surge.sh

図解のポイント:
- 変更点: （何が変わったか）
- 今すぐ試せる: （操作の要点）
- 活用シーン: （フリーランスでの使いどころ）

この図解を削除したいとき:
チャット欄で「この図解を削除して」と伝えてください。
```

#### 公開できなかった場合

```
完成: 【機能名】の図解

（変更点を1〜2文で要約）

ファイルの保存先:
output/{スラッグ}.html（ブラウザにドラッグ＆ドロップすると表示できます）

図解のポイント:
- 変更点: （何が変わったか）
- 今すぐ試せる: （操作の要点）
- 活用シーン: （フリーランスでの使いどころ）
```

### 図解の削除

「この図解を削除して」と依頼された場合:

1. 直近にデプロイしたURLを確認する（削除したいURLをユーザーに確認する）
2. `npx surge teardown {ドメイン}` を実行する
3. 削除完了を伝える

## 守ること（禁止事項）

- **React・shadcn/ui を使わない** — 静的なHTMLのみ
- **絵文字を使わない** — アイコンはLucide Iconsを使う
- **インタラクティブ要素を入れない** — アニメーション・トグル・フォームは禁止
- **`<style>` タグを追加しない** — Tailwind CSSクラスで完結させる（テンプレートのCSS変数定義は除く）
- **`<script>` を追加しない** — Lucide初期化スクリプト以外禁止
- **外部画像URLを使わない** — CDN（Tailwind・Lucide）以外の外部リソース禁止
- **古い情報を載せない** — 必ずWebで最新情報を確認してから生成する

## コンテンツ生成の指針

- **1機能に絞る** — 迷ったら「フリーランスに最も実用的なもの」を1つ選ぶ
- **「今すぐ試せる手順」を必ず含める** — 知識だけでなく、操作できる状態になることがゴール
- **フリーランス活用の視点を入れる** — AI学習・副業・フリーランス業務でどう使えるか
- **ビフォーアフターで変化を見せる** — 「以前はこうだった → 今はこうなった」の対比
- **制限・注意点は1行で** — 補足セクションを作らず、利用条件バッジと1行の注記で完結させる
- **出典を必ず載せる** — 最後のカードに出典リンクをまとめる
- **日本語で** — 英語のアップデートも図解は日本語で書く
